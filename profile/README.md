<h2>手机上做电商运营，最先要解决的是「不掉线」</h2>
<p>手机端配置住宅 IP 的技术难度不高，真正的问题是稳定性。从 Wi-Fi 切到移动数据、进出电梯丢信号、双卡切换、系统省电杀后台，每一次网络状态变化都可能让代理失效，而且多数情况下不会有任何提示。你看到的是「照常能刷」，实际已经回落到本地出口。</p>
<p>所以手机端的配置重点不是「怎么填」，而是「怎么保证一直生效」。</p>

<p>做店铺运营的手机，建议用系统 VPN 客户端或随身路由。Wi-Fi 代理只适合固定在办公室的那台设备。</p>

<h2>安卓与 iOS 的配置差异</h2>
<p>安卓：进入设置，网络与互联网，当前 Wi-Fi 详情，代理设置改为手动，填地址与端口，保存后重连。若用客户端，导入配置后连接并授权。</p>
<p>iOS：设置，无线局域网，当前网络右侧信息按钮，滑到底部配置代理，选手动，填服务器与端口，存储后重连。</p>
<p>两者的共同点是「按网络保存」，换网络要重配。这一点决定了它不适合移动场景。</p>

<h3>认证填写容易出错</h3>
<p>用户名与密码区分大小写，特殊字符要按原样输入。部分服务要求把认证信息按特定格式拼接，格式错了会直接连接失败。拿不准时先要一个示例格式。</p>
<h3>省电策略会杀连接</h3>
<p>安卓的省电优化可能中断后台连接，表现为「锁屏一段时间后断线」。需要把客户端加入不受限制名单。iOS 的后台刷新限制也有类似影响，需要在设置里放开。</p>

<h2>静默失效怎么防</h2>
<p>三个动作。一，开启客户端的断线阻断，断线时阻止流量走本地。二，把出口查询页面加到主屏幕，切换网络后点一下确认。三，观察应用行为，若突然出现本地化内容或语言变化，说明出口已变。</p>
<p>第一个最有效，代价是断线时无法上网。对需要稳定身份的场景，这个代价值得付。</p>

<h2>电商场景的额外要求</h2>
<p>一，一台手机对应一个店铺主体。手机是最容易混用的设备，两台店用同一部手机登录，出口不同也会被关联。</p>
<p>二，固定网络环境。不要在 Wi-Fi 与移动数据之间来回切换，因为两种线路的出口可能不同。</p>
<p>三，关闭可能泄漏位置的权限。部分应用会读取定位，与出口地区矛盾时会产生额外信号。</p>

<h2>验证清单</h2>
<p>一，出口地址与归属正确。二，DNS 解析与出口同地区。三，目标应用（不只是浏览器）能正常使用。四，锁屏一段时间后连接仍在。五，切换网络后连接仍在或能快速恢复。</p>
<p>第四项与第五项是手机端特有的，桌面端不需要考虑。这两项不过关，配置再对也用不久。</p>

<h2>常见故障</h2>
<p>故障一，浏览器能用、应用不能用。应用不读系统代理，需客户端接管。</p>
<p>故障二，锁屏后断线。省电策略导致，需加入白名单。</p>
<p>故障三，切换网络后失效。Wi-Fi 代理的固有限制，改用客户端。</p>
<p>故障四，连上但很慢。多为手机端走了中继，或信号本身弱。先排除信号因素。</p>

<h2>常见问答</h2>
<h3>能用同一部手机管多个店吗</h3>
<p>技术上可以，但风险高于一机一店。手机指纹、传感器特征很难完全隔离。</p>
<h3>需要装专用软件吗</h3>
<p>支持标准协议的方案，用系统设置或通用客户端即可。专用软件功能更多，但增加依赖。</p>
<h3>热点共享给电脑可靠吗</h3>
<p>临时应急可以，长期不建议。手机发热明显，且稳定性不如随身路由。</p>
<h3>出国漫游时怎么办</h3>
<p>漫游时出口通常是漫游地，与预期可能不符。需要固定地区的，不要依赖漫游。</p>
